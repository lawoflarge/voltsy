# Voltsy v1.2 — "Care & Trust" Update — Design Spec

- **Date:** 2026-06-13
- **Status:** Approved (brainstorming) → ready for implementation plan
- **App:** Voltsy: Battery Life Buddy (App Store id `6778094814`, live v1.0 since 2026-06-13)
- **Target:** v1.2.0 / Build 9
- **Predecessor spec:** `docs/superpowers/specs/2026-06-08-voltsy-design.md`

## 1. Context

Voltsy is live: a cute battery-care app whose mascot **Volt** reacts to the battery
level, with a daily care loop, care score, streaks, achievements, a Home Screen widget,
a charging Live Activity, and a weekly recap. Free with an AdMob banner + €4.99 lifetime
Pro (`com.lawoflarge.voltsy.pro`, removes ads). 63 tests green, SwiftUI / iOS 26,
monorepo (`apps/Voltsy` + `apps/VoltsyWidget` + `packages/VoltsyKit`).

This update does three things: (a) ship the highest-demand, on-brand new features the
competitive/user research surfaced, (b) refresh App Store Optimization, and (c) fix the
broken ad delivery so the free tier actually earns — without compromising the trust angle.

### Competitive/demand findings that drive this design (from 3 research sweeps)

- **The unoccupied intersection = Voltsy's moat:** utility incumbents (Battery Life,
  Ampere, Battery HD) are cold, ad-spammy, and *distrusted*; cute apps (Pixel Pals,
  Widgetable, BunnyWatch) are loved but shallow. Nobody combines *cute mascot + honest +
  gentle care-habit loop*.
- **Honesty is a selling point, not a handicap.** iOS exposes only `batteryLevel`
  (~5%-rounded since iOS 17), `batteryState`, `thermalState` (4-level, no °C), and
  `LowPowerMode`. The category bleeds 1-star reviews over jumpy/faked health numbers.
  Voltsy already refuses to fake health % / cycle count — surface that as credibility.
- **#1 user want:** "tell me when to unplug" (charge alarm, esp. 80%) + two-way
  high/low threshold alerts. Must be framed as a best-effort *nudge* (iOS background
  delivery is unreliable), never a guaranteed alarm or hard stop.
- **#1 trust-killer:** intrusive ads. Voltsy's edge is *not being BunnyWatch*. Ads must
  work but stay dezent; revenue leans on Pro (the Pixel Pals model: free core + paid
  cosmetics/extras).

### Locked decisions (this session)

- **Scope = v1.2 "solid update"** (features below). Cosmetics/skins, iCloud sync, Watch
  complication, and an app-preview video are explicitly deferred to v1.3.
- **Ad strategy = dezent + protect trust:** fix delivery (publish EU CMP, link AdMob app
  to the store listing) and add the banner to 1–2 *secondary* surfaces only. Never the
  mascot Home. No interstitials. Grace period stays.

## 3. Feature spec

Honesty invariant applies to every feature: never render a fabricated number; gate any
estimate behind sufficient data; never claim iOS-restricted hardware data.

### FREE

**F1 — Two-way charge alerts (basic, fixed thresholds).**
*What:* local notifications for "Volt is full — unplug to keep the battery young" (at the
charging high threshold) and "Volt is fading — find a charger" (low). Each Volt-voiced.
*How:* the pure `VoltNotificationEngine` **already produces these messages**
(`.fullChargeNudge` at ≥0.80 charging, `.lowBattery` at ≤0.15 unplugged, `.overheating`).
Work = wire them into the scheduler/foreground path. The app observes
`UIDevice.batteryLevelDidChangeNotification` / `batteryStateDidChangeNotification`; on a
qualifying transition while active, fire an immediate local notification, with
de-duplication so the same nudge doesn't repeat within a charge session.
*Honesty/constraint:* best-effort — delivered when the app observes the change (foreground
or brief background wake during charging). Copy and the Trust screen state it is a nudge,
not a guaranteed background alarm. Fixed defaults in Free; customization is Pro (P1).
*Free defaults:* unplug nudge at 80%, low alert at 15% (match engine constants).

**F2 — Trust screen ("Why no battery health %?").**
*What:* a calm explainer: "Apple doesn't let any app read your real battery health or
cycle count — here's how to check it yourself in Settings → Battery → Battery Health," plus
a one-liner on the iOS-17 5% rounding (pre-empts "your % disagrees with the status bar").
*How:* a static SwiftUI view reachable from Home (e.g. an info affordance / settings entry)
and linked from the care card's existing honesty caption. Deep-link to Settings where
possible (`UIApplication.openSettingsURLString`; battery-health deep link is best-effort).
*Why:* turns the platform limit into the credibility moat; defuses the category's #1
1-star theme before it happens.

**F3 — Volt's Care Tips (evidence-based coaching).**
*What:* a small, reassuring tips surface. Content (locked, evidence-based): heat is enemy
#1 (don't charge under a pillow / in a hot car; remove case if hot); stay in the ~20–80%
"healthy middle" (or use Optimized Charging / ~90%); prefer slower charging when not in a
hurry. Myth-busting: overnight charging is fine; draining to 0% to "calibrate" is a relic.
*How:* a pure content model (`CareTip` list) in `BatteryEngines` (testable: each tip has a
title/body/icon; selection helper can surface a contextually relevant tip), rendered in a
SwiftUI list/cards view. Tone is anti-anxiety, never fear-mongering.
*Honesty:* all guidance is general habit advice; no per-device claims.

**F4 — Contextual Volt caption (mood-aware one-liner).**
*What:* a short line under Volt on Home that reacts to the *current* state: overheating →
"I'm running warm — maybe take my case off"; LPM (`.zen`) → "Resting to save power 💤";
critical → "Running low — find me a charger". Today Home shows only `mood.rawValue`.
*How:* moods already exist (`VoltStateMapper` maps `.overheating`/`.zen`/`.critical` etc.;
`Volt.swift` already renders 8 expressions). Add a pure `VoltCaption.text(for:)` mapping
mood → copy (testable), render it under the mascot. Small, high-warmth, low-risk.

**F5 — Discharge ETA ("time left").**
*What:* an honest "~Xh left" estimate while unplugged, mirroring the existing charge ETA.
*How:* new pure engine (or extend `ChargeEstimateEngine`) — `DischargeEstimateEngine`,
TDD. Estimate the discharge rate from the most recent contiguous unplugged run via
`SessionEngine.sessions`; gate it (run ≥ N min + meaningful negative delta) → return nil
rather than a fabricated number. Surfaced as a subtle line near the care card; never shown
when confidence is insufficient.
*Honesty:* labeled an estimate; hidden when ungated (same discipline as charge ETA).

**F6 — Review prompt at positive moments.**
*What:* request an App Store rating via `SKStoreReviewController`/`requestReview`, but only
after a *positive* moment — a streak milestone (e.g. day 3/7) or a completed full charge —
and never on a frown/critical/overheating state. Frequency-capped (system already caps to
~3/year; add our own once-per-positive-milestone guard persisted in UserDefaults).
*Why:* a new app is rating-starved; review velocity is itself a ranking factor. Asking only
on delight protects the average.

### PRO (unlocks via existing `com.lawoflarge.voltsy.pro`)

**P1 — Custom alert thresholds.**
*What:* Pro users set the unplug-at-X% and low-at-Y% thresholds (Free = fixed F1 defaults).
*How:* a settings view (Pro-gated) writing thresholds to persisted prefs; F1's scheduler
reads them. The pure selection logic stays in `VoltNotificationEngine` (pass thresholds in
instead of the current hard-coded 0.80/0.15 — refactor constants to parameters, keeping the
Free defaults). Tested.
*Gate:* non-Pro sees the control with a Pro lock → Paywall.

**P2 — Charge history + trend graph.**
*What:* a line graph of charge level over time ("your charge level over time" — honestly
labeled, never "capacity"/"health"). Free = last 24h/7 days; Pro = full retained history.
*How:* data already persists via `BatteryStore` (SwiftData `BatterySampleRecord`). Add a
pure aggregation (downsample samples → chart points; e.g. `ChargeHistoryEngine`, TDD) and a
SwiftUI `Charts` view. Free/Pro gating is a windowing parameter on the query. No new
storage; respects the on-device, no-account posture.
*Honesty:* axis/labels make clear it is the charge *level* over time, not battery capacity.

## 5. AdMob fix (dezent)

Root cause of "no ads on iPhone 13" (diagnosed from code + project history), in order of
impact for an EEA/German user:
1. **Banner only lives in the Weekly Recap** — never on a primary surface → ~0 impressions.
2. **EU GDPR/UMP consent message not published for Voltsy** → in the EEA `canRequestAds`
   stays false → `ConsentManager.canShowAds` never flips → `AdGate` blocks → no ad ever.
3. **AdMob app `4806029723` not linked to the store listing** → 0% fill (NetGuard lesson).
4. Grace period (first 3 sessions ad-free) + new-app fill ramp (minor).

Fix:
- **Publish the EU consent message** for Voltsy in the AdMob console (extend the existing
  CMP setup; privacy URL `voltsy.vercel.app/privacy.html` is live). Likely Safari +
  trusted-click automation per the GDPR-CMP playbook (Levin authorizes the login).
- **Link AdMob app → store listing** `6778094814` (Safari), then await store propagation.
- **Add the banner to 1–2 secondary surfaces** — the new **Charge History** and **Care
  Tips** screens — gated by the same `AdGate` (Pro-free, consent-required, grace). Home
  stays pristine; no interstitials. This raises impressions honestly.

No code change to `AdGate`/`ConsentManager` logic is required for the fix itself; the
config (CMP + link) is the unblock. Banner placement is additive view work.

## 10. Risks & mitigations

- **Background alert reliability (F1/P1):** iOS won't reliably run code to catch an exact %.
  → frame as best-effort nudge; be explicit in copy + Trust screen; lean on charge-session
  observation. Do not market a "guaranteed 80% alarm."
- **ASO "battery health" rejection risk:** keep "health" to *tips/care* framing; never imply
  a real health % readout in copy or screenshots.
- **CMP publish friction (EEA):** AdMob console is Safari + trusted-click; may need a Levin
  login. Until published, EEA ads stay gated (acceptable — non-blocking for the build).
- **Ad placement creep:** strictly two secondary surfaces; never Home, never interstitial,
  to protect the anti-BunnyWatch trust position.
